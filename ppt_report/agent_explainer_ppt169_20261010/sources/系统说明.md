# 系统说明：德国光伏政策组合多主体模型（Solar PV Policy Mix ABM）

> 本文档用于帮助理解本系统的整体结构、复现目标、当前进度与运行方式，便于向他人汇报。

---

## 1. 项目是什么

本系统是对论文《*Beyond innovation and deployment: Modeling the impact of technology-push and demand-pull policies in Germany's solar policy mix*》（Nuñez-Jimenez et al., 2022, *Research Policy*）补充材料（Supplementary Information）所描述 ABM（Agent-Based Model，多主体/基于智能体的模型）的**计算机复现**，并在此基础上**用大语言模型（LLM）Agent 增强主体决策能力**。

论文研究德国 1991–2016 年光伏（Solar PV）产业如何在一系列"技术推动（technology-push，如政府研发投入）"与"需求拉动（demand-pull，如上网电价补贴 FiT）"政策组合下扩散。模型通过模拟三类主体——**采用者（居民/企业）**、**制造商（组件生产商）**、**安装商（渠道）**——之间的互动，复现德国光伏装机量的历史演化轨迹。

因此，项目有两条并列的主线：

1. **模型复现**：忠实还原论文 SI 中的主体定义、调度流程与数学公式。
2. **LLM Agent 接入**：让部分主体（制造商、采用者）的决策由 LLM 替代传统公式，探索"LLM 驱动 ABM"的可行性。

## 2. 系统架构

### 2.1 三类核心主体（Agent）

| 主体 | 角色 | 数量 | 决策方式 |
|------|------|------|----------|
| **Adopter**（采用者） | 光伏系统的潜在买家，分三类：住宅（residential）、工商业（commercial/industrial）、电站（utility-scale） | 500（1:1000 缩比） | 两阶段公式 + LLM|
| **Manufacturer**（制造商） | 组件生产商，分国内（德国）与国外（如中国） | 2 | 双因子经验曲线公式 + LLM |
| **Installer**（安装商） | 安装/渠道环节，分国内与国外 | 2 | 纯公式（劳动力市场） |

另有一个**观察者（MacroEnvironment，宏观环境）**，负责提供每个月的电价、FiT 补贴、媒体关注度、政府研发强度等外生数据（合成数据或真实历史数据两种模式）。

### 2.2 每个 tick（= 1 个月）的调度顺序

严格按论文 SI §1.1.5 的 5 步执行（`model/solar_model.py`）：

1. **更新宏观变量**：读取当月电价 / FiT / 媒体关注度 / 研发强度。
2. **采用者决策**：未安装的采用者评估是否安装，产生新需求进入安装队列。
3. **安装商响应**：从安装队列中按产能逐步消化订单，调整员工与 BOS 成本。
4. **制造商技术更新**：结算累计产量、更新知识存量，用经验曲线更新组件成本。
5. **时钟推进**：记录本月装机量、就业、价格等指标。

整个模拟周期为 **312 个月 = 26 年（1991–2016）**。

## 3. 模型复现的核心机制

### 3.1 采用决策：论文"两阶段"模型（`submodels/adoption.py`）

论文的采用决策不是单一公式，而是**两阶段**过程：

**阶段一 · 萌生念头（Ideation，Equation 2）**
主体当且仅当四个变量加权和超过阈值 **0.5** 时才"萌生安装念头"：

```
k_peers·PE + k_info·IN + k_awareness·AW + k_attractive·IRR > 0.5
```

- `PE`：1 km 内已装邻居比例（peer effects）
- `IN`：当月光伏信息量（logistic 拟合世界累计装机）
- `AW`：环境意识（N(0.5, 0.2)，赋值后恒定）
- `IRR`：代表家庭的内部收益率（经济吸引力）
- 权重（Table SI 11）：peers=0.19、info=0.17、awareness=0.52、attractive=0.12

**阶段二 · 经济与环境评估（Equations 3–10）**
只有"萌生念头"的主体进入此阶段：

- **早期采用者**（环境意识 > 0.92 且为住宅用户）→ 直接安装；
- 其余主体分别计算 **国内组件** 与 **国外组件** 的 NPV，选择**非负且最大**者（平局偏好国内）。

NPV 折现 20 年现金流，包含自发自用省费、余电上网 FiT 收入、运维成本，并对国外组件加一个 1.1% 的折现溢价（Table SI 10）。

### 3.2 组件成本：双因子经验曲线（`submodels/experience_curve.py`）

组件成本由**干中学（learning-by-doing）**与**研究中学（learning-by-research）**双驱动：
干中学指累计产量越高、成本越低；研究中学指知识存量越多、成本越低。

```
MC = α · (CP/CP₀)^β_LBD · (KS/KS₀)^β_LBR
```

参数已对齐论文 Table SI 53：

| 参数 | 国内 | 国外 | 非组件(BOS) |
|------|------|------|------|
| 截距 α | 2.882 | 2.448 | 3.354 |
| β_LBD（干中学） | −0.074 | −0.448 | −0.155 |
| β_LBR（研究中学） | −0.814 | −0.074 | — |

### 3.3 安装商：劳动力市场（`submodels/labor_market.py`）

安装商根据订单积压情况决定招人/裁员，BOS 成本随供需关系浮动，形成市场降温的负反馈。

## 4. LLM Agent 接入

### 4.1 设计思路

在公式模型之上，让 **Manufacturer** 和 **Adopter** 的决策改由 LLM 完成，并保留**确定性公式回退**：一旦 LLM 调用失败（网络错误、返回格式异常、速率限制等），自动回退到经验曲线 / 两阶段采用公式，保证模型永远可运行。

### 4.2 关键组件

- **BaseLLMAgent**（`agent_framework.py`）：封装 AsyncOpenAI 客户端、记忆注入、结构化 JSON 输出、工具调用循环、确定性回退。
- **ConversationMemory**：滚动 6 轮记忆，让主体"记住"自己过去的决策，实现多轮上下文。
- **Tool / ToolRegistry**：OpenAI function-calling 格式的工具，LLM 决策前可先查询实时市场数据（电价/FiT/组件价格/邻居采用率/回收期等）。
- **Pydantic 校验**：`ManufacturerDecision`、`AdopterDecision` schema 严格校验 LLM 输出结构。
- **异步并发**：`asyncio.gather` 并发调用多个主体的 LLM 决策。

### 4.3 制造商的董事会群决策（`agents/board.py`）

制造商的月度决议不再由单次 LLM 调用产生，而是**召开董事会投票**：

- **5 名 AI 董事**，各有独立人格、职责与固有偏好：董事长（长期战略）、CFO（现金流与产能利用率）、CTO（技术与研发）、CMO（订单与市场需求）、CSO（合规与稳健）。每位董事是一个独立的 LLM agent，拥有**自己的记忆**（记录历次投票），因此同一董事在不同月份的立场具有连续性。
- **议程**：议案A 产能（expand / maintain / reduce + 强度 0–0.5）；议案B 研发重点（efficiency / cost_reduction / none）。每位董事都可以对任一项**弃权**（"决定要不要投票"）。
- **表决规则**：`过半门槛 = 董事数 // 2 + 1`（5 人 → 3 票）。达到门槛且唯一领先者即通过；平票由资历最靠前的董事（董事长）裁决；有效票不足门槛或全员弃权 → 本次会议无决议，回退到经验曲线规则（`fallback_used=True`）。
- **强度合成**：通过 expand/reduce 时，强度取投该选项的董事强度均值；maintain 强度恒为 0。
- **可见性**：每场会议都会输出完整纪要——每位董事的投票、强度、把握、中文理由与顾虑，以及两张议案计票表。纪要同时（a）打印到控制台、（b）追加写入 `board_logs/board_minutes_<时间戳>.md`、（c）以结构化字段存进仿真 history（`domestic_board` / `foreign_board`），供 `analysis/metrics.py` 汇总（会议数、一致通过率、平票次数、未达半数次数、平均反对/弃权票数、议案分布）。
- **成本**：每 tick 每个厂商 5 次 LLM 调用（2 家厂商 = 10 次/tick），312 tick 约 3120 次厂商调用。用 `--no-board` 可退回单 LLM 决策。

> 注：董事会决议同样只产生"决策"，状态更新仍由 `apply_llm_decision` 执行一次；LLM/董事会失败时的公式回退也遵循同一契约，不会重复扣减/累加状态。

## 5. 当前结果与进度

- 结果如图所示：四个面板分别是累计装机 / 组件成本 / 累计采用者 / 政策与价格信号，可以看到采纳是被政策点燃的，不是自发的。
- 引入LLM后，结果与原文的偏差主要有两处：
- 偏差一是采用率偏高，模型 10%，真实约 7%；LLM的采用行为会偏离经济理性。公式路径里 NPV 为负的绝不装；LLM 路径没有这道闸，理论上会出现"财务上不划算但仍然装"的决策，也能表达从众、情绪、政策预期这类公式写不出来的理由。方向上会让采用曲线更早启动或更早饱和（取决于 prompt 里给的信号）。
- 偏差二是国外成本塌缩，模型 0.084 €/W，真实约 0.3 €/W


| 主线 | 进度 | 说明 |
|------|------|------|
| 模型复现 | **~95%** | 主体定义、5 步调度、两阶段采用、双因子经验曲线、劳动力市场、宏观环境、分析可视化均已落地 |
| LLM Agent 接入 | **~75%** | DeepSeek 已接线并端到端跑通（刚修复 JSON 解析回退 bug），工具调用、记忆、并发、回退均已工作 |

### 已修复

**LLM 回退 bug**：DeepSeek 返回的决策 JSON 常被散文和 Markdown 代码块包裹（如 `Let me analyze...\n```json\n{...}\n``` `），导致 `model_validate_json` 解析失败、所有决策静默回退到公式。已在 `agent_framework.py` 新增 `extract_json_object()` 助手，剥离围栏与散文后提取 `{...}` 再解析，并在 manufacturer/adopter/BaseLLMAgent 四处调用点统一替换。冒烟测试确认：Manufacturer 与 Adopter 均走真实 LLM 决策（0 回退）。

### 单元测试

`pytest tests/` → **93 个测试全部通过**（新增 6 个 `extract_json_object` 测试）。

2026-10-08 追加：`pytest tests/` → **114 个测试全部通过**（新增 21 个董事会群决策测试，含端到端集成测试：桩 LLM → 董事会过半表决 → 决议驱动厂商成本/产能 → 纪要落盘与 metrics 汇总）。

## 6. 运行方式

```bash
python main.py               # 公式模式，312 tick，约 12–15s（无 LLM）
python main.py --real-data   # 使用真实历史数据
python main.py --llm         # LLM 模式，默认开启董事会群决策（读 .env 的 DEEPSEEK_API_KEY）
python main.py --board       # 同 --llm，但显式打开董事会（5 名董事过半表决）
python main.py --llm --no-board   # 退回单 LLM 决策（每 tick 2 次厂商调用）
pytest tests/ -v             # 114 个测试
```

董事会模式下，每场会议纪要会打印到控制台并写入 `board_logs/board_minutes_<时间戳>.md`。

公式模式结果（seed=42，合成数据）：最终约 50/500 采用（10%）、0.6 MW；国内成本 2.833 → 0.399 €/W（−85.9%），国外 2.444 → 0.084 €/W（−96.6%）。

## 7. 已知局限与待办

1. **采用率略高**：10% vs 真实 ~7%。根因是邻居半径用了 10 km（论文 1 km）作为 500 主体缩比的补偿；改回 1 km 需空间索引支撑 2 万主体并重新标定。
2. **国外成本塌缩**：制造商 CP 用了 `max(global_cum, own_CP)` 世界累计装机，导致国外成本被过度压低到 0.084 €/W（真实 ~0.3）。经调查（测试记录第十三轮），字面"改回自产 CP"会回归（国外 2.24、国内 0.761 €/W），根因是国外制造商产量由全球市场驱动（外生）、缩比模型无法内生复现。正确修复需：修正 `global_cum` 量级（~10 倍膨胀）+ 为国外制造商引入外生区域产量序列。
3. **主体规模**：500 主体（1:1000 缩比）导致装机量绝对值偏小；增大到 2 万需空间索引（当前邻居计算 O(n²)）。
4. **成熟 Agent 框架**：尚未接入 LangChain / AutoGen 等多步推理框架。
5. **模型校准**：尚未逐图/逐表对比论文输出做完整校准。
